# 使用模拟任务集（P1-P3 验证）

> 在 `D:\桌面\step-cli-pi` 目录下执行。需要先 `pnpm build` 确保 `dist/` 存在。

---

## 任务 1：Plan mode 工具拦截视觉验证（P1）

**场景**：开启 plan mode 后，模型尝试调用写文件工具，验证拦截卡片显示为黄色 `✗` + `[plan mode]` 标记。

**步骤**：
1. `pnpm step` 启动 TUI
2. 输入 `/plan` 开启计划模式
3. 输入 `请把 "hello" 写到 src/hello.txt` 之类的写文件请求
4. 观察模型调用 `write_file` 时的卡片渲染

**验收标准**：
- 状态符为黄色（`✗` 是黄色），不是红色
- 工具名后紧跟 `[plan mode]` 标记
- 结果体文字为黄色
- 与普通错误工具（红色 `✗`）一眼可区分

**预期结果**：用户能直观看出「这是 plan mode 拦截，不是工具故障」。

---

## 任务 2：普通工具错误视觉不变（P2 回归）

**场景**：普通模式下工具执行失败，验证仍为红色 `✗`，不受 `errorCode` 映射影响。

**步骤**：
1. `pnpm step` 启动 TUI
2. 输入一个会失败的 bash 命令，如 `bash -c "exit 1"` 或调用一个不存在的工具
3. 观察错误卡片的渲染

**验收标准**：
- 状态符为红色 `✗`
- 结果体为红色
- 无 `[plan mode]` 标记

**预期结果**：普通错误视觉零变化。

---

## 任务 3：PlanApproval 长计划折叠/展开（P3）

**场景**：模型提交一个超长计划，验证 approval 弹层默认折叠，`Ctrl+E` 可展开。

**步骤**：
1. `pnpm step` 启动 TUI
2. 输入 `/plan` 开启计划模式
3. 让模型生成一个超长计划（10 行以上），然后调用 `exit_plan_mode`
4. 观察 approval 弹层：
   - 默认状态：只显示前 10 行，底部有 `↳ 还有 N 行（Ctrl+E 展开）`
   - 按 `Ctrl+E`：展开全部内容，底部切换为 `… 已展开全部 N 行 · Ctrl+E 收起`
   - 再按 `Ctrl+E`：重新折叠回前 10 行

**验收标准**：
- 短计划（≤10 行）无折叠提示，无 `Ctrl+E` 提示
- 长计划默认折叠，有 `Ctrl+E` 提示
- `Ctrl+E` 切换流畅，内容完整

**预期结果**：长计划不占用过多屏幕空间，需要时一键展开。

## 任务 4：InlineApproval 预览折叠不变（P3 回归）

**场景**：`write_file` / `edit_file` 审批时，预览折叠行为保持不变。

**步骤**：
1. `pnpm step` 启动 TUI
2. 输入一个写文件请求，如 `write_file src/test.txt` 带较长内容
3. 观察审批弹层的预览区域

**验收标准**：
- `write_file` 显示行号预览，超过 10 行时折叠
- `edit_file` 显示 diff 预览，超过 10 行时折叠
- `Ctrl+E` 展开/收起正常
- 底部提示为 `· Ctrl+E 展开预览` / `· Ctrl+E 收起预览`

**预期结果**：原有审批预览折叠功能无回归。

## 任务 5：Windows 启动兼容性（P4 前置）

**场景**：在 Windows 上通过 `pnpm step` 启动 TUI，验证无 `@opentui/core` 相关报错。

**步骤**：
1. 在 Windows 终端（PowerShell / CMD / Git Bash）执行 `pnpm step`
2. 观察启动输出

**验收标准**：
- 无 `Unknown file extension .scm` 错误
- 无 `bun:ffi` protocol not supported 错误
- TUI 正常进入交互界面（看到输入框和状态栏）

**预期结果**：Windows 用户可直接 `pnpm step` 启动，无需手动干预。

---

## 任务 6：长对话滚动性能（P5 前置观察）

**场景**：开启 plan mode 并触发多次工具调用，观察转录区滚动是否流畅。

**步骤**：
1. `pnpm step` 启动 TUI
2. 开启 plan mode
3. 连续触发多次工具调用（如多次 `read_file`）
4. 观察终端滚动和重绘是否卡顿

**验收标准**：
- 转录区滚动无明显卡顿
- 状态栏刷新正常
- 无 `doRender` 宽度断言崩溃

**预期结果**：为后续 P5 调优建立基线观察。

---

## 执行说明

- 所有任务需在真实终端中手动执行（TUI 交互无法完全自动化）
- 任务 1-3 需关注渲染颜色和标记，建议在支持 ANSI 颜色的终端中执行
- 任务 5 仅在 Windows 环境下执行
- 每次任务完成后记录：通过 / 不通过 + 现象描述
